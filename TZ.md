## 1. Общие сведения о проекте

**Название проекта:** (не указано, далее — CRM)
**Тип:** B2B-система для фулфилмент-оператора.
**Цель:** автоматизация работы с селлерами Wildberries по модели FBS.

**Бизнес-контекст:**
- Сейчас всё ведётся в Excel и «в голове».
- В CRM работают: администратор, менеджеры склада, селлеры.
- Один физический склад.
- Текущая нагрузка: 100–150 заказов в день. Целевая: до 10 000 заказов в день.
- Интеграция с Wildberries только по API FBS.
- Товары с Честным знаком обязательны к привязке.

## 2. Архитектура и технологии (требования)

| Компонент | Требование |
|-----------|------------|
| Тип приложения | Веб-приложение (сайт), работает в браузере |
| База данных | Любая (реляционная или NoSQL). Критерии: надёжность, простота, масштабируемость |

## 3. Роли пользователей и права доступа (жёстко)

### 3.1. Администратор (владелец)
- Полный доступ ко всему.
- Управление селлерами (добавление, редактирование, удаление, токены).
- Управление товарами, ячейками, остатками (включая редактирование).
- Настройка ценовых групп и индивидуальных цен.
- Просмотр всей финансовой информации (выручка, обороты).
- Доступ ко всем отчётам и дашбордам.

### 3.2. Менеджер фулфилмента
**Работает ТОЛЬКО с заказами и складскими операциями.**
- Приёмка товаров (сканирование, ввод количества).
- Смена номеров ячеек (переназначение).
- Формирование листа подбора, сборка, печать этикеток FBS.
- Формирование поставок, печать ШК поставки.
- Сканирование возвратов (через кнопку «Возврат»).
- **НЕ ВИДИТ ЦЕН, СТОИМОСТИ, ВЫРУЧКИ И ЛЮБЫХ ФИНАНСОВЫХ ДАННЫХ.**
- **НЕ РЕДАКТИРУЕТ** селлеров, товары, остатки (кроме списания через сборку).

### 3.3. Селлер (клиент)
- Отдельный личный кабинет с логином/паролем (генерируется системой).
- Видит только свои данные:
  - Остатки товаров (в штуках).
  - Количество заказов за день и за неделю.
  - (В будущем) свою задолженность за обработку.
- **НЕ ВИДИТ ЧУЖИХ ДАННЫХ И ФИНАНСОВ ДРУГИХ СЕЛЛЕРОВ.**
- Может нажать кнопку «Обновить данные» для ручной синхронизации с WB.

## 4. Модуль управления селлерами (администратор)

### 4.1. Добавление селлера
- Доступно админу или менеджеру (но без права редактирования финансов).
- Вводится: ИП/название компании.
- После создания система генерирует логин и пароль для селлера (отправляется менеджером/админом селлеру).
- **Обязательно:** привязка API-токена WB с полными разрешениями для FBS.

### 4.2. Карточка селлера (для админа)
- Список всех товаров селлера с баркодами, ячейками, остатками.
- Назначение ценовой группы (или индивидуальной цены).
- История операций (приёмка, списания, возвраты).

---

## 5. Модуль приёмки товара

### 5.1. Приёмка для существующего товара
1. Сотрудник сканирует баркод товара.
2. Вводит количество единиц.
3. Система автоматически подставляет номер ячейки (где уже лежит этот баркод).
4. Остатки увеличиваются на введённое количество.
5. Данные синхронизируются с WB (остатки обновляются).

### 5.2. Приёмка для нового товара (новый баркод)
1. Сотрудник сканирует баркод.
2. Вводит количество.
3. Система видит, что баркод новый.
4. Два варианта:
   - **Автоматически** — система сама назначает свободную ячейку.
   - **Вручную** — менеджер или админ выбирает номер ячейки (для сортировки по размерам/артикулам).
5. Ячейка привязывается к этому баркоду навсегда (для данного селлера).
6. Остатки увеличиваются.
7. Синхронизация с WB.

### 5.3. Правила хранения
- Один баркод = одна ячейка (но в ней может быть много единиц).
- На каждой коробке/ячейке этикетка: название селлера, баркод товара, номер ячейки.
- Этикетки генерируются и печатаются системой.

---

## 6. Модуль заказов FBS (синхронизация с WB)

### 6.1. Режимы синхронизации
- **Автоматическая:** каждые 10–20 минут (запрос новых заказов и статусов по API).
- **Ручная:** кнопка «Обновить данные» в кабинете селлера или менеджера (перед финальной сборкой).

### 6.2. Формирование листа подбора (внутренний)
1. Система запрашивает у WB сборочные задания (лист подбора WB).
2. Преобразует их в **свой внутренний лист подбора** с группировкой по ячейкам:

| Ячейка | Баркод | Количество собрать |
|--------|--------|---------------------|
| №1     | 460...  | 5 шт.              |
| №3     | 462...  | 8 шт.              |

3. Лист подбора можно распечатать.

---

## 7. Модуль сборки и печати этикеток FBS

### 7.1. Процесс сборки
1. Сотрудник идёт с листом подбора.
2. Берёт из ячейки №1 — 5 шт., из ячейки №3 — 8 шт. и т.д.
3. Подходит к рабочему месту с принтером.

### 7.2. Печать этикетки FBS
1. Сотрудник сканирует баркод конкретного заказа (на товаре или упаковке).
2. Система сравнивает с листом подбора.
   - **Если баркода нет в листе** → звуковой сигнал + красное табло (ошибка).
   - **Если есть**:
     - Система мгновенно запрашивает по API WB этикетку FBS для этого заказа.
     - **Вариант А:** этикетка сразу печатается (автоматически).
     - **Вариант Б:** на экране появляется номер заказа и этикетки, сотрудник нажимает Enter — печать.
3. Этикетка клеится на коробку/пакет.

### 7.3. Требование по скорости
- От сканирования до печати — **менее 2 секунд**. Сотрудник не должен ждать.

---

## 8. Модуль Честного знака (маркировка)

### 8.1. Обязательная привязка
- Для товаров с обязательной маркировкой привязка кода DataMatrix (КИЗ) к этикетке FBS — **обязательна**.
- **Без этой привязки товар НЕ МОЖЕТ БЫТЬ ОТПРАВЛЕН**.
- Система блокирует передачу статуса в WB, пока код не отсканирован и не привязан.

### 8.2. Процесс привязки
1. После печати этикетки FBS сотрудник сканирует код DataMatrix с упаковки товара.
2. Система привязывает его к этому заказу в кабинете WB через API.
3. Статус привязки отображается в системе.

---

## 9. Модуль формирования поставок

### 9.1. Условия формирования
- Поставка формируется ТОЛЬКО после того, как ВСЕ заказы в ней:
  - Собраны.
  - Упакованы.
  - Оклеены этикетками FBS.
  - (Для маркированных) привязаны коды Честного знака.

### 9.2. Печать ШК поставки
- Доступна только после выполнения всех условий выше.
- Система запрашивает через API WB штрихкод поставки.
- **Тип кода:** общий QR-код для сортировочного центра (без грузомест, просто штора поставки).
- Печать осуществляется ТОЛЬКО из CRM.
- ШК клеится на видимое место на поставке.

---

## 10. Модуль списания остатков

- После того как поставка сформирована и ШК распечатан, система **автоматически** списывает собранные товары с остатков склада (ячеек).
- Списание происходит только для товаров, которые реально переданы в WB (статус поставки подтверждён).

---

## 11. Модуль возвратов

### 11.1. Кнопка «Возврат»
- Отдельная кнопка в интерфейсе менеджера.
- Принцип работы идентичен приёмке, но:
  - Сканируется баркод товара.
  - Вводится количество.
  - Система добавляет товар обратно на остаток в ту же ячейку.
- Возврат помечается отдельным флагом/файлом, чтобы селлер и админ видели, что это возврат, а не новая поставка.

---

## 12. Модуль ценообразования и финансов

### 12.1. Ценовые группы (габаритные)
- Администратор создаёт 4–5 групп (например: малогабаритный, средний, крупный, негабарит, сверхнегабарит).
- Для каждой группы задаётся стоимость обработки за 1 единицу.

### 12.2. Привязка товара к группе
- При добавлении товара (или редактировании) администратор выбирает группу → цена подставляется автоматически.
- Если цена не задана — стоимость не отображается.

### 12.3. Индивидуальная цена (ручной ввод)
- В карточке товара есть поле «Индивидуальная стоимость».
- Если оно заполнено — приоритет выше групповой цены.
- Администратор может найти товар:
  - по баркоду
  - по номеру ячейки
- И вручную изменить цену для этого конкретного товара.

### 12.4. Финансовая аналитика (только админ)
- По каждому селлеру: количество заказов × стоимость = выручка.
- Отчёты за день, неделю, месяц, всё время.
- Оборот по всем селлерам агрегированно.

## 13. Дашборды и отчёты

### 13.1. Дашборд администратора (главный экран)
- Количество подключенных селлеров.
- Общее количество заказов за сутки / неделю / месяц / всего.
- (Без списка товаров и детализации по селлерам на главном экране.)

### 13.2. Дашборд внутри селлера (для админа)
- Детализация по конкретному селлеру:
  - Остатки по каждому товару.
  - Заказы за день/неделю.
  - Выручка за день/неделю/месяц/всё время (на основе стоимости обработки).
  - Возможность просматривать и редактировать цены/группы.

### 13.3. Кабинет селлера
- Видит только свои остатки и свои заказы (за день/неделю).
- В будущем — видит свою сумму задолженности.

### 13.4. Ежедневные отчёты (автоматические)
- Отчёт по количеству заказов за день.
- Отчёт по товарным остаткам.
- Формируются автоматически (например, в конце дня).

## 15. Интеграция с API Wildberries (FBS)

Обязательные вызовы:
- Получение списка новых заказов.
- Получение сборочных заданий (лист подбора).
- Получение этикетки FBS для заказа.
- Обновление остатков (передача количества).
- Привязка кода Честного знака к заказу.
- Формирование поставки.
- Получение ШК поставки.
- Отправка статуса готовности заказа.

**Все вызовы — через API-токен селлера.**

---

## 16. Примечания и допущения

- Честный знак — обязателен для маркированных товаров.
- Товар без привязки Честного знака не отправляется.
- Менеджер не видит финансов ни при каких условиях.
- Селлер получает доступ только к своим данным.
- Система должна работать с двумя моделями принтеров Xprinter (365 и 370).
- Выбор стека и БД — на усмотрение разработчика.
- В будущем: возможна привязка стоимости обработки и отображение суммы в кабинете селлера.
