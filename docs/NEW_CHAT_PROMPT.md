## ТЕКУЩАЯ ЗАДАЧА (блокер, приоритет №1)

**Проблема:** при сборке FBS на вкладке **«На сборке»**, режим **«Скан»** (не «Лента»), после сканирования **баркода заказа из листа подбора** должно **автоматически появляться окно «Сканируйте Честный знак»** (DataMatrix) — как в TZ §7.2 и §8.2.

**Сейчас:** поле баркода **очищается** и снова активно окно ввода баркода. Окно ЧЗ **не появляется** (или мелькает и сразу пропадает). В таблице заказов у товара виден значок **ЧЗ**.

**Простая логика (как в ТЗ):**
- баркод найден в листе + товар с ЧЗ → **сразу** переключить UI на поле Честного знака;
- без ЧЗ → сразу печать стикера FBS;
- **никогда** не вызывать `resetScanFlow()` / не возвращать на баркод, пока ЧЗ не отсканирован или пользователь не нажал «Отмена».

**Уже пробовали 5+ раз без успеха на проде** (коммиты `7182ed6` … `a98af0b`). Не повторяй те же правки вслепую — **воспроизведи цепочку**, проверь ответ `POST /api/orders/assembly/sellers/{id}/scan-print/` (`action`, `requires_marking`, коды ошибок).

**Ключевые файлы:**
- `frontend/src/pages/AssemblySellerPage.tsx` — `handleBarcodeSubmit`, `openMarkingScan`, `resetScanFlow`, `scanPhase`, `pendingOrder`
- `backend/apps/orders/services/assembly.py` — `scan_order_barcode`, `_order_requires_marking`, `_assert_scan_in_pick_list`, `_match_order_by_scan`
- `frontend/src/pages/AssemblyPage.css` — `.assembly-scan-step--hidden`

**Подозрения для проверки:**
1. `resetScanFlow()` в `catch` после ошибки API (особенно `not_in_pick_list`)
2. Несовпадение формата баркода (сканер vs таблица vs лист подбора)
3. Backend возвращает `action: print` вместо `await_marking`
4. Активен режим «Лента» (`BatchBindPanel`) вместо «Скан»
5. Старый JS на сервере / не прошёл build
