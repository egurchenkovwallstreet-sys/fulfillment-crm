**Решение (`2cdaeec`):** `add_orders_to_supply()` в `wb_client.py` — пачки по 100.

## 3. ЧЗ: повторный скан после ошибки WB + номер стикера

**Проблема:** после отклонения ЧЗ WB повторный скан баркода не открывал шаг привязки ЧЗ (заказ оставался в `label_printed`).

**Решение (`8451972`):**
- при скане баркода заказ с `marking_verify_status=error` сбрасывается (снятие sgtin в WB) → снова шаг 3;
- при любой ошибке ЧЗ в ответе и UI — **обязательно номер стикера** (`sticker_part_a / sticker_part_b`);
- печать FBS-стикера в Chrome как в инвентаризации: одно окно → `print()` → `close()` (без пустого popup);
- исправлен «залипший» фокус: `scanPhaseRef`, мгновенный переход на поле ЧЗ.

## 4. Панели очереди ЧЗ (фон, без моргания экрана)

**Проблема:** фоновая проверка ЧЗ перезагружала весь экран → моргание; модалки мешали сканированию.

**Решение (`440585b`):**

### Две панели на вкладке «На сборке»

| Панель | Считает | Цвет |
|--------|---------|------|
| **Ошибки ЧЗ** | WB отклонил маркировку | 🟢 0 / 🔴 N |
| **Без ЧЗ** | Товар с обязательной маркировкой, ЧЗ ещё не привязан | 🟢 0 / 🔴 N |

- Клик по панели → список: **фото, размер, баркод, номер стикера**;
- в списке ошибок — кнопка **«Заменить товар»**;
- работа в списках — тот же флоу: баркод → ЧЗ → печать стикера (панель скана справа).

### Фоновая проверка WB

- **Не обновляет** всю таблицу заказов и **не показывает** модалки во время скана;
- первая проверка — **через 3 сек**, далее **каждые 3 сек** (`verify-marking`);
- панели обновляются **каждые 4 сек** (`GET marking-status/`).

### Блокировка доставки

Пока хотя бы одна панель **красная** (число > 0) — кнопки **«В доставку»** и **«Все готовые в доставку»** неактивны.

### Быстрый переход баркод → ЧЗ

- `flushSync` — переключение на поле ЧЗ **до** фоновых запросов;
- поле баркода **убирается из DOM** на шаге ЧЗ;
- `scanBusy` вместо общего `loading` — экран не мигает;
- blur баркода сразу при Enter.
