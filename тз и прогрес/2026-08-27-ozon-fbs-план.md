# Ozon FBS — полный пошаговый план реализации

**Дата:** 27.08.2026  
**Статус:** план утверждён, реализация начата  
**Правило:** схема **FBS** (как WB). FBO не делаем.

---

## Согласованная логика (TZ)

- Один клиент (ИП) может работать на **WB и Ozon**, токены разные.
- Товары разные (баркоды разные) → **ячейки разные**. Нумерация своя у каждого маркетплейса.
- Этикетка: **одна** 75×120, две зоны — номер не уменьшать; снизу максимально крупно **ВБ** / **OZON**, ИП и баркод.
- Регистрация: выбор WB / Ozon / оба. Селлер видит только назначенное. Второй маркетплейс можно подключить позже.
- Менеджер: вкладка WB или Ozon → главная этого маркетплейса. Цвета как в ЛК.

**Авторизация Ozon:** заголовки `Client-Id` + `Api-Key` (ЛК seller.ozon.ru → Настройки → API-ключи). Не один токен, как у WB.

---

## Соответствие вкладок

| CRM | WB | Ozon FBS |
|-----|----|----------|
| Новые | `supplierStatus=new` | `awaiting_packaging` |
| На сборке | `confirm` | сборка в CRM (скан, ЧЗ, этикетка) |
| В доставке | `complete` + `waiting` | `awaiting_deliver` (ждёт сдачи в пункт Ozon) |
| Стикер | стикер WB 58×40 | этикетка отправления PDF |
| Поставка | QR поставки WB | акт + ШК отгрузки Ozon |
| ЧЗ | `PUT .../meta/sgtin` | `mandatory_mark` при `/v4/posting/fbs/ship` |

Методы списка отправлений — **v4** (`/v4/posting/fbs/list`, `/v4/posting/fbs/unfulfilled/list`). v3 отключают.

## Шаги реализации

### Шаг 1 — Каркас маркетплейса — **сделано 27.08.2026**
1. Поля селлера: `wb_enabled`, `ozon_enabled`, `ozon_client_id`, `ozon_api_key_encrypted`, кэш счётчиков Ozon.
2. Ячейка и товар: поле `marketplace` (`wb` / `ozon`), уникальность `(seller, marketplace, number/barcode)`.
3. Вкладки WB / Ozon на главной, цвета темы (WB `#CB11AB`, Ozon `#005BFF`).
4. Селлер видит только свои маркетплейсы; менеджер — оба.
5. Создание селлера: галочки WB / Ozon; кнопка «+ Ozon» / ключи Client-Id + Api-Key.
6. Этикетка ячейки: **одна** 75×120 — номер как был (~60%); снизу маркетплейс максимально крупно + ИП + баркод.
7. Склад / приёмка / XL / ячейки / инвентаризация фильтруются по вкладке.
8. Клиент Ozon API: ping складов, счётчики `awaiting_packaging` / `awaiting_deliver` на дашборде.

### Шаг 2 — Клиент Ozon API — **сделано 27.08.2026**
9. `ozon_client.py`: склады, список FBS **v4** (`/v4/posting/fbs/list`, fallback unfulfilled).
10. Проверка ключей при сохранении.
11. Синк складов FBS Ozon (`SellerOzonWarehouse`, как WB).
12. Дашборд Ozon: живые счётчики после «Обновить данные Ozon».

### Шаг 3 — Каталог и склад Ozon — **сделано 27.08.2026, остатки 29.08.2026**
12. Онбординг карточек Ozon → ячейки по размерам (мастер «Склад → Подключение» на вкладке Ozon).
13. Приёмка и XL-приёмка на вкладке Ozon — ячейки Ozon.
14. Остатки на склад Ozon — кнопка «Отправить остатки CRM на склад Ozon».

### Шаг 4 — Сборка FBS Ozon — **сделано 29.08.2026**
15. Модель отправления Ozon, синк `awaiting_packaging` / `awaiting_deliver`.
16. Лист подбора по ячейкам — позже.
17. Скан баркода → «На сборке». Этикетка PDF (`/v2/posting/fbs/package-label`) и ЧЗ (`mandatory_mark` при ship).
18. «В доставку» вызывает `/v4/posting/fbs/ship` и списывает остаток CRM.
19. Акт / ШК: `/v1/carriage/create` + `/v1/carriage/approve` (не устаревший act/create).
20. Списание остатков при отгрузке — есть.
21. Скан DataMatrix на вкладке «На сборке»; кнопка «В доставку» без ЧЗ заблокирована.

## Порядок для новичка после деплоя шага 1

1. Ctrl+F5.
2. Вверху — вкладки **WB** и **Ozon**.
3. Селлеры → при создании отметить маркетплейсы.
4. Для Ozon — вставить Client-Id и Api-Key.
5. Склад → Подключение: загрузить каталог Ozon, подтвердить ячейки. При необходимости — «Отправить остатки CRM на склад Ozon».
6. Сборка Ozon: «Обновить из Ozon» → вкладки Новые / На сборке / В доставке. Скан баркода → при ЧЗ скан DataMatrix → «В доставку». Через минуту — «Этикетка». Для сдачи в пункт — «Сформировать акт и ШК».
