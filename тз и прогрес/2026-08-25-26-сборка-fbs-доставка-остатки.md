## 1. Статус «в доставке, но ещё не принят на складе WB»

Источник истины — WB Marketplace API (`POST /api/v3/orders/status` + `GET /api/v3/supplies`).

| Уровень | Поле | Значение | Смысл в ЛК WB |
|---------|------|----------|---------------|
| Заказ | `supplierStatus` | **`complete`** | Собран и передан в доставку |
| Заказ | `wbStatus` | **`waiting`** | «Ждёт сортировки» — **ещё не принят на СЦ WB** |
| Поставка | `done` | `true` | Поставка передана в доставку |
| Поставка | `scanDt` | **пусто** | ШК поставки **не отсканирован** на складе WB |

**После приёмки на складе WB:**
- `wbStatus` → **`sorted`** («Отсортирован»)
- `scanDt` заполняется
- заказ **исчезает** из вкладки «В доставке» в ЛК WB и из списка сборки FBS

**Не входят в «В доставке»:** `sorted`, `sold`, `ready_for_pickup`, `defect`, отмены.

## 2. Счётчик vs список на вкладке «В доставке»

| Элемент UI | Логика | Должен совпадать с |
|------------|--------|---------------------|
| **Синяя карточка (счётчик)** | `complete + waiting` из **live API** при синке → кэш `seller.wb_count_delivery` | Вкладка «В доставке» в **ЛК WB** |
| **Список заказов** на вкладке | `complete + waiting` **и** заказ в подтверждённой поставке CRM с `wb_scanned_at IS NULL` | Операционный список «ждут сканирования ШК поставки» |

**Баг 26.08.2026 (ИП Мазирка):** карточка показывала **303**, в ЛК WB — **209**.

**Причина:** счётчик брал размер списка по поставкам (`delivery_stage_orders_queryset`), а не live-счётчик WB; ~94 заказа в БД имели устаревший `wb_status=waiting`, хотя в WB уже `sorted`.

**Исправление (`c723f7b`, `SYNC_VERSION = delivery-v14`):**
- счётчик вкладки = `seller.wb_count_delivery` (из API, `complete + waiting`);
- `reconcile_stale_delivery_orders()` — сверка «зависших» `waiting` с WB при каждом синке;
- список на вкладке по-прежнему через `delivery_stage_orders_queryset()`.

## 3. Списание остатков при доставке через ЛК WB

**Проблема:** заказы, переданные в доставку **напрямую в ЛК WB** (не через CRM), не списывали остаток на складе фулфилмента.

**Решение (`5555e25`):**

| Изменение | Файл |
|-----------|------|
| Синк всех поставок `done=true` из WB (в т.ч. созданных в ЛК) | `orders/services/supply_sync.py` |
| Привязка заказов к `Supply`, статус `CONFIRMED`, обновление `complete+waiting` | `supply_sync.py` |
| Списание через `deduct_stock_for_confirmed_supply()` | `warehouse/services/stock_deduction.py` |
| Fallback: `deduct_pending_delivery_stock()` для заказов в доставке без списания | `stock_deduction.py` |
| При «Обновить заказы»: сначала статусы, затем поставки + scanDt | `orders/services/sync_orders.py` |

## 7. Проверка после деплоя

1. `cd /opt/fulfillment-crm && git pull && bash scripts/deploy.sh`
2. Сборка FBS → селлер → **«Обновить заказы»**
3. Счётчик «В доставке» = число в ЛК WB (`complete + waiting`)
4. Заказ, переданный в доставку через ЛК WB → остаток на складе CRM уменьшается
5. После сканирования ШК поставки на WB → заказ исчезает из списка вкладки
