## Требование по ТЗ (§7.2, §8.2)

На вкладке **«На сборке»**, режим **«Скан»** (не «Лента»):

1. Менеджер сканирует **баркод заказа** из листа подбора.
2. Если у товара **ЧЗ** (`requires_marking`, значок «ЧЗ» в таблице) — **мгновенно** (без ожидания API) появляется жёлтое окно **«Сканируйте Честный знак»** с полем DataMatrix.
3. После скана ЧЗ → привязка в WB (`sgtin`) → **сразу** печать стикера FBS 58×40.
4. Если товар **без ЧЗ** → сразу печать стикера, без окна ЧЗ.

**Простая логика:** баркод в листе + ЧЗ в таблице → окно ЧЗ; иначе → печать.  
Пока шаг ЧЗ открыт — **не** возвращаться к полю баркода (только «Отмена»).

## Что сломалось после режима «Лента»

Режим ленты (`6e6f5d3`) сам по себе рисует другой UI (`BatchBindPanel`). Баг был в **режиме «Скан»**, но всплыл в той же ветке: появилось несколько листов подбора, сверка баркода стала строже, а UI скана начали «лечить» CSS-скрытием двух полей сразу.

Симптом: поле баркода очищается, снова активно «Сканируйте баркод». Окно ЧЗ не появляется или мелькает.

---

## Реальные причины в коде (не повторять патчи `7182ed6`…`a98af0b`)

1. **`resetScanFlow()` не был замком.** Даже при optimistic-открытии ЧЗ `finishPrint` / `catch` / `useLayoutEffect` могли вернуть фазу на баркод. `useLayoutEffect` делал `scanPhaseRef.current = scanPhase` и затирал ref со старым стейтом.
2. **Оба поля (баркод + ЧЗ) всегда в DOM**, ЧЗ прятался через `.assembly-scan-step--hidden`. Поле баркода с `autoFocus` после `scanBusy=false` снова забирало фокус; визуально это «окно ЧЗ пропало».
3. **`_match_order_by_scan` брал `.first()`** по баркоду. При нескольких заказах одного SKU выбирался уже собранный/без ЧЗ → `action: print` вместо `await_marking`.
4. **Сверка с сохранённым листом, а PDF/экран — preview вкладки «На сборке».** Баркод из бумаги/таблицы мог не быть в `PickList` NEW → `not_in_pick_list` → сброс UI, хотя заказ с ЧЗ виден в таблице.
5. **Нормализация баркода разная:** фронт сравнивал с учётом ведущих нулей, бэкенд — нет; сканер мог прислать GS1 FNC1 / AIM-префикс `]C1`.
6. **`Product.objects.filter(seller, barcode).first()` без `marketplace=wb`.** После Ozon та же строка баркода могла притянуть карточку Ozon без ЧЗ → `action: print`, хотя в таблице значок ЧЗ (WB-карточка).

## Что сделано

**Frontend (`AssemblySellerPage.tsx`):**
- `markingLockRef`: `resetScanFlow()` **не** возвращает на баркод, пока lock (снимается только «Отмена», смена режима, успешная печать после ЧЗ).
- Заказ для скана: все совпадения по баркоду, **приоритет у строки с ЧЗ** (не первая попавшаяся).
- Поле ЧЗ **монтируется вместо** поля баркода (не два инпута с `display:none`).
- Убран опасный `scanPhaseRef.current = scanPhase` из layout-effect.

**Backend (`assembly.py`):**
- Одинаковая нормализация баркода (пробелы, `.0`, ведущие нули, FNC1, AIM).
- Выбор заказа: сначала тот, которому **нужен** скан ЧЗ.
- Скан разрешён, если баркод в активном WB-листе **или** это заказ текущей сборки (`in_picking` / `assembled`).
- Подстановка товара только с `marketplace=wb`.
