## 1. Регрессия: заказы пропадали сразу после «В доставку» из CRM

### Симптом
После передачи поставки в доставку из CRM: счётчик «В доставке» = 0, список пуст, поставки «ждущие scanDt» не видны.

### Причина
Коммит `58f7909` в `_wb_supply_scanned_at()` использовал **`closedAt`** как fallback для «сканирования на складе WB».  
WB ставит `closedAt` **сразу при передаче в доставку** (`done=true`), до физического скана ШК поставки.  
Фоновый sync (~500 мс после deliver) закрывал заказы как `SHIPPED` и ставил `supply.wb_scanned_at`.

### Исправление (`5e6501c`)
| Изменение | Файл |
|-----------|------|
| Приёмка на СЦ WB — **только `scanDt`**, не `closedAt` | `orders/services/supply_sync.py` |
| Автовосстановление: сброс ошибочного `wb_scanned_at`, возврат заказов во «В доставке» | `supply_sync.py` → `_revert_premature_supply_scans()` |
| Ночная сверка 4:00 — только по `scanDt` | Celery `reconcile_stuck_delivery_orders` |

**Правило (зафиксировано в TZ §6.3):** `closedAt` = момент передачи в доставку; `scanDt` = момент скана ШК поставки на СЦ.

## 2. «Призрачные» заказы из ЛК WB блокировали новую сборку

### Симптом
Один заказ передали в доставку через **ЛК WB** (не CRM). В CRM он не виден на вкладках сборки, но при передаче **новой** поставки — ошибка «1 заказ не собран».

### Причина
Заказ оставался в M2M `Supply ↔ Order`, но `wb_supplier_status = complete` / `IN_DELIVERY` — не проходил `order_can_send_to_delivery()`.  
Проверка `_assert_all_supply_orders_ready_for_deliver()` учитывала **все** заказы поставки, включая невидимые в UI.

### Исправление (`8f76315`)
| Изменение | Файл |
|-----------|------|
| `order_departed_wb_assembly()` — заказ уже не на сборке WB | `orders/services/wb_status.py` |
| Исключение из `assembly_supply_orders()` | `orders/services/supply_flow.py` |
| Автооткрепление от активной поставки (`FORMING`/`READY`) | `refresh_supply_readiness()` |
| **Принудительная передача** (`force=true`) — только собранные заказы | API `POST .../supplies/{id}/deliver/` |
| Кнопка внизу вкладки «Готовые», двойное подтверждение | `AssemblySellerPage.tsx` |

## 3. Статистика отгрузок по товарам для владельца

**Страница:** `/owner/product-stats`  
**Коммиты:** `f03c9b7` → `ef9a361` → `a6f8299` → **`1322053`** (финал)

### Требование
Штуки отгруженных товаров по селлеру и баркоду, **без ₽**, за день / неделю / месяц / всё время / свой период, поиск по баркоду, полная история CRM.

### Источник данных (финал)
| Маркетплейс | Источник | Условие |
|-------------|----------|---------|
| **WB** | `StockOperation` тип `SHIPMENT` | комментарий содержит **`стикер FBS`** (первая печать стикера в CRM) |
| **Ozon** | `StockOperation` тип `SHIPMENT` | комментарий начинается с **`Ozon `** |

**Не считаются:** повторная печать стикера, печать без списания (остаток 0), статусы WB, журнал «В доставку», legacy-списания «поставка WB».

**API:** `GET /api/sellers/admin/product-stats/` → `"source": "sticker_stock_deduction"`.

**Файлы:** `sellers/services/crm_product_stats.py`, `OwnerProductStatsPage.tsx`.
